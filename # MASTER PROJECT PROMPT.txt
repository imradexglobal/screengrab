## 10. LEARNING ENGINE

Implement an incremental statistical pattern-learning engine. Reuse existing learning logic if it is correct and can be improved safely.

Support patterns of lengths:
- 4 categories
- 5 categories
- 6 categories
- 7 categories
- 8 categories

For example:

S, N, N, B

The engine should learn which next category historically followed a pattern and record how often each candidate outcome occurred.

Track:
- Pattern length
- Pattern sequence
- Candidate next group
- Observed opportunities
- Resolved predictions
- Correct predictions
- Incorrect predictions
- Empirical accuracy
- Recent performance, where enabled
- Relevant timestamps
- Model version

Learning must start from the beginning of the dataset.

**Do not wait for 1,000 readings before learning or predicting.**

Once enough prior categories exist, the model must start making predictions. For example, a four-category pattern becomes available after four eligible prior category observations.

The 1,000-record rule applies only to automated clicking.

### Correct prediction timing

Every prediction must be created using only information available at the prediction time.

When the next accepted category arrives:
1. Find unresolved predictions awaiting that outcome.
2. Compare each prediction with the actual category.
3. Mark it correct or incorrect.
4. Update pattern statistics.
5. Generate new predictions based on the currently available history.

Do not use future readings to calculate historical prediction confidence.

Keep individual prediction events in persistent storage.

Learning continues even when:
- Automated clicking is disabled.
- The prediction does not qualify for clicking.
- The predicted category is not selected for clicking.
- Fewer than 1,000 valid records exist.

### Pattern selection

Do not automatically assume the longest pattern is best.

Shorter patterns may have more evidence. Longer patterns may be more specific but have less evidence.

Use a documented, deterministic strategy to select a candidate prediction from available patterns.

If competing patterns conflict and no candidate meets the defined selection criteria, report no eligible prediction rather than inventing certainty.

The statistical engine must be independently testable without requiring actual screen capture or mouse clicks.

## 11. CONFIDENCE AND EVIDENCE

Default confidence threshold: 70%.

The initial threshold comparison must be strictly greater than the configured threshold. Exactly 70% does not qualify when the threshold is 70%.

Calculate empirical accuracy using resolved predictions only.

For example, 21 correct outcomes from 30 resolved predictions equals 70% historical accuracy. It is not a guarantee of future performance.

Track:
- Correct count
- Resolved prediction count
- Incorrect count
- Overall empirical accuracy
- Recent accuracy, where enabled
- Evidence sufficiency
- Prediction eligibility

Implement a configurable minimum evidence requirement. Suggested initial default: 30 resolved predictions for the relevant pattern/candidate pair.

Implement a configurable recent-performance safeguard. Suggested initial default: recent accuracy of at least 60%, using a clearly defined recent window.

These evidence and recent-performance settings may be configurable. The 1,000-record click gate must not be configurable.

A candidate with insufficient evidence must not authorize a click.

Preserve the confidence and evidence available at the time each individual prediction was created.

## 12. MANDATORY 1,000-RECORD AUTOMATION GATE

This is an absolute requirement.

**No automated click may be dispatched until Region A has at least 1,000 qualifying, persisted, valid readings.**

This rule is mandatory and non-editable.

It must be enforced inside the automation execution path, not merely through the UI.

It must not be bypassed by:
- Enabling auto-click in settings
- Changing the confidence threshold
- Importing unrelated or invalid events
- Recalculating the model
- Restarting the app
- Editing an ordinary setting
- Counting Region B data
- Counting OCR attempts
- Counting failed or invalid readings
- Counting predictions instead of readings

Before every click, query the qualifying Region A reading count from the persistent database or a reliable transactionally maintained count.

Required behavior:
- 0 valid records: no click.
- 999 valid records: no click.
- 1,000 valid records: the count condition may pass, but every other safety condition must also pass.

The gate must be independently unit-tested.

If the existing database contains historical readings, assess them during migration. Count only records that meet the defined valid Region A criteria. Do not manufacture valid records to satisfy the threshold.

## 14. RECALCULATE APP BRAIN

Add a button labelled exactly:

**Recalculate App Brain**

Place it in the learning/patterns interface.

This function rebuilds derived learning data from the preserved raw reading history.

### Preserve original data

Never delete or rewrite:
- Original readings
- Raw OCR text
- Reading timestamps
- Stable reading IDs
- Capture metadata
- Existing settings
- Range configuration history
- Click rules and coordinates
- Historical click audit logs

Rebuild derived classification, prediction, and pattern data as required.

Do not pretend historical click actions were executed again during recalculation.

### Required recalculation process

1. Notify the user that the derived model will be rebuilt.
2. Confirm the operation if appropriate.
3. Immediately block new automated clicks.
4. Record the current model and configuration versions.
5. Obtain a consistent source-reading snapshot.
6. Reclassify numeric readings using the current valid ranges.
7. Replay eligible Region A readings chronologically.
8. Generate each historical prediction before exposing the next actual outcome to the predictor.
9. Resolve predictions when their actual subsequent outcomes become available.
10. Recalculate pattern counts, accuracy, confidence, and recent performance.
11. Validate the new model.
12. Publish the new model atomically.
13. Record model version, source count, completion time, and result.
14. Display success or a useful error.

Use transactions, staging tables, versioned derived records, or an equivalent safe approach appropriate to the existing database.

Do not drop or recreate the entire database to rebuild the model.

If recalculation fails:
- Preserve the previous published model.
- Do not publish partial results.
- Preserve raw readings and historical click logs.
- Keep auto-click disabled until the model is valid.
- Show the error and allow a retry.

If new readings arrive during recalculation, handle them deterministically using a snapshot and a controlled catch-up process, or pause processing safely.

### Rebuild triggers

Request recalculation when changes invalidate the derived model, including:
- Range boundaries
- Category identities that affect pattern interpretation
- Pattern lengths
- Prediction-selection logic
- Confidence/evidence calculation logic
- Historical reading imports or corrections
- Learning algorithm changes

Changing only the click location or turning auto-click on/off should not require retraining unless prediction semantics are affected.

The app must show whether the current model is valid, stale, rebuilding, or failed.
